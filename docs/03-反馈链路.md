# 三个工作区 → 派单方 的反馈链路（负责人 2026-10-31 要求）

## 一、解决的问题

```
原来：工作区把结果写成 outbox 文件 → 派单方不会主动读 → 负责人 不问就永远不知道
现在：每个工作区干完活调一条命令 → 报告同时到三个地方 → 派单方和 负责人 立刻知道
```

## 二、一条命令搞定

```
node bin/report.mjs <工作区> "<一句话结论>" "<详细内容>" [--ask]
```

**`--ask` = 这件事需要派单方拍板**（会挂起，15 分钟没人回会自动催 负责人）。

例子：

```
node report.mjs alice "三组参数跑完了" "A +2.3% / B +5.07% / C +4.49%，推荐 C" --ask
node report.mjs bob "两套材料整理好了" "链接 × 2，脱敏检查已过"
node report.mjs carol "入口核实完了" "入口在首页第二屏，需要实名认证"
```

## 三、报告同时去哪三个地方

| 去处 | 谁看 | 怎么看到 |
|---|---|---|
| `data\tasks\reports\<工作区>\<时间>.md` | 存档 | 直接看文件 |
| `harness-control\channel.jsonl` | **派单方** | 用 `bridge_read` / `report_read` 工具 |
| 派单方账号私聊 负责人 | **负责人** | 微信/QQ 直接收到（不用来问） |

**关键**：聊天消息是用**派单方的账号**发出去的，所以 负责人 那边看到的就是派单方在跟他汇报，不需要派单方再复述一遍。

## 四、派单方那边新增的查看工具

```
report_read  看三个工作区报上来的反馈（带 ⚠️需拍板 标记）
bridge_read  看频道里的全部内容（现在三个工作区的都包含）
```

## 五、需要拍板时会发生什么

```
1. 报告挂起 → data\harness-control\pending-decision.json
2. 15 分钟没回 → QQAgent-DshWatchdog 私聊 负责人 催一次
3. 派单方用 bridge_answer 把 负责人 的决定写回 → 工作区读到继续
```

## 六、三个工作区各自的规矩

| 工作区 | 什么时候报告 |
|---|---|
| alice（我） | 每做完一件需要 负责人/派单方知道的事 |
| bob | 接到单、交付完、需要报价或选方案时 |
| carol | 核实完入口、需要选目标方时 |

**不需要报告**：纯查询、自己内部重试、没结论的中间态。


## 八、通知策略（负责人 2026-10-31 定）

```
默认安静：report.mjs 不带 --ask → 只写文件 + 频道，不推 QQ
需要拍板：report.mjs --ask     → 推送 负责人 + 挂起等回复（15 分钟没回再催一次）
强制推送：--notify             → 显式要求打扰（很少用）
```

理由：负责人 不想被日常进度打扰，只在「要他做决定」时找他。
