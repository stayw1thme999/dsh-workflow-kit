# 01 任务与派单

## 一、接收方是什么

「接收方」是**你自己起的名字**，代表一个能接活的对象：

- 一台机器上的一个 DSH 会话
- 一个机器人 / 一个子进程
- 一个真人同事
- 甚至一个目录（比如 `inbox-财务`）

本工具**不预设任何分工**。我们的用法是我们的，你的用法取决于你——写几个接收方、谁干什么，全由 `config.json` 决定。

```json
{ "receivers": ["alice", "bob"] }
```

加接收方不用改代码：配置里写名字，`init` 会给它建信箱。

## 二、派一单的完整流程

```bash
# 1. 建单（spec 是 JSON，字段见 templates/工单-spec.md）
node bin/wo.mjs new -f spec.json

# 2. 校验（验收标准写没写、依赖是否存在）
node bin/wo.mjs check WO-20260101-0001

# 3. 派给某个接收方（不给就谁闲谁拿）
node bin/wo.mjs assign WO-20260101-0001 alice

# 4. 接收方领取（依赖没完成会被拒）
node bin/wo.mjs take alice

# 5. 上报进度
node bin/wo.mjs report WO-20260101-0001 "写完一半"

# 6. 交验收（证据必填）
node bin/wo.mjs submit WO-20260101-0001 "产物路径 + 输出原文"

# 7. 验收
node bin/wo.mjs accept WO-20260101-0001
```

## 三、轻量派单（不用工单）

只想传个话、不需要验收时，用信箱：

```bash
# 把一封信放进 alice 的信箱
#   <workspace>/tasks/mailbox/alice/2026-01-01T10-00-00-000Z-t1.md

# alice 收信（取一封，取完进 _done）
node bin/take.mjs --window alice
```

## 四、巡检（可选）

想让接收方没人盯也能自己动，就在每个会话里挂一个定时提醒（`docs/02-巡检prompt.md`），间隔自己定。

```bash
node bin/patrol.mjs alice --quiet
```

输出一行：信箱 / 队列 / 工单 / 未读 / 失败 / 心跳。退出码 0 正常、1 有问题。

## 五、几条规矩（少扯皮）

1. **一条任务只派一个接收方**
2. **派之前先看队列**，同标题别重复派
3. **领了就要标 doing**（`take` 自动标），做完必须 `submit` 或 `done`
4. **跨接收方的活写成两条**，别混在一张单里
5. **任务里带路径/链接**，别让接收方再猜一遍
6. **卡住必须贴原文**（`wo.mjs block <id> "<报错原文>"`）

## 六、数据落在哪

```
<workspace>/tasks/
├─ mailbox/<接收方>/*.md      信箱（收完进 _done/）
├─ receivers/<接收方>.json    接收方状态
├─ workorders/pool.json       工单池
├─ dispatch.jsonl             派单记录
└─ failures.jsonl             失败台账
```
