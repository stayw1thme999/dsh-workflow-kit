# 失败必须贴原文，不许静默绕路（负责人 2026-11-01 定）

## 一、铁律

```
任何工作区，任何脚本，出错就贴报错原文，禁止：
  · catch {} 里什么都不干，假装成功
  · 失败后自己降级成另一个方案，不吭声
  · 报告里写「已完成」其实跳过了某一步
```

**理由（负责人 原话）**：*绕过去等于把 bug 藏了。*

## 二、怎么贴

```
node bin/fail.mjs <工作区> "<在做什么>" "<报错原文>"
```

- 报错原文从 **stderr / 异常栈**里复制，**不要改写成「失败了」**
- 拿不到原文就写 `(没有拿到报错原文)`
- 也可以从标准输入喂：

```
node bin/fail.mjs alice "跑批处理" -
```

**它会做三件事**：

```
① 追加到 data\tasks\failures.jsonl（可追溯）
② 写进频道 channel.jsonl（派单方 bridge_read 能看到）
③ 写一条 urgent 上下文留言（她下次醒来必看到）
```

## 三、查询

```
node bin/fail.mjs list 20     看最近 20 条失败
```

## 四、禁止清单（看到就是违规）

```
✗ try { ... } catch { }                      —— 空 catch
✗ catch (e) { console.log('失败') }           —— 只写"失败"不贴原文
✗ if (err) { return ok }                     —— 把失败当成功
✗ 失败后换一条路继续，且没在任何地方记一笔
✗ 报告里说"已验证"但实际跳过了验证步骤
```

## 五、自查工具

```
node bin/scan-silent-catches.mjs
```

扫出所有「catch 里什么都不做」的位置。**当前扫到 453 处**——这些不是都要改（比如清理临时文件失败可以忽略），但**涉及主流程的必须先改**：

```
优先级高：claim.mjs / dispatch.mjs / mailbox.mjs / monitor / guard / preopen / report.mjs
优先级低：清理临时文件、读取可选配置、日志目录不存在
```

## 六、例外（允许吞掉的）

```
· 清理临时文件失败
· 可选的配置文件不存在
· 日志目录创建失败（已经不影响主流程）
```

**例外也必须留一行注释说明为什么能吞**，比如：

```js
} catch { /* 临时文件清理失败不影响结果 */ }
```
