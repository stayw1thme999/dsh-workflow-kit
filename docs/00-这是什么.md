# 00 这是什么

DSH 的工作单元是**会话**。一个人开几个会话干活没问题，但一旦有两个以上的人/会话同时接活，就会撞上四个问题：

1. 谁该干哪条？（没有派单）
2. 干完了怎么让人知道？（没有回写）
3. 卡住了怎么让人看见？（没有留证）
4. 没人管的时候谁来叫醒？（没有巡检）

这套 kit 就是把这四个问题变成**文件和几条命令**：

| 问题 | 机制 | 文件 |
|---|---|---|
| 谁干哪条 | 信箱投递 + 接收方自取 | `data/tasks/mailbox/<接收方>/*.md` |
| 干完怎么回写 | dispatch done / wo submit | `data/tasks/dispatch.jsonl` |
| 卡住怎么留证 | fail 必须贴报错原文 | `data/tasks/failures.jsonl` |
| 谁叫醒 | 每 20 分钟巡检提醒 | DSH schedule |

设计原则只有三条：

- **状态在文件里，不在人脑里**——换会话/换机器都能接着干
- **失败必须贴原文**——禁止静默绕路，绕一次等于藏一个 bug
- **越少越稳**——只做流转，不做编排智能；判断留给人和模型
