# 多窗口自主 Agent 系统 · 架构文档

> 用途：把散落的脚本 + 规范 + 经验，归纳成一份能对外陈述的架构。供工作/合作/面试讲清"这套系统是什么、怎么协作、为什么这样设计"。
> 生成：拆解层 2026-11-06

## 一、一句话定位

**不是"一个更聪明的 AI"，是"一套让多个 AI 不翻车、不烧钱、不说谎地协作的治理底座"。**
AI 的能力（会执行）是通用的、免费的；「知道该解决什么问题 + 判断结果对不对 + 让一群 AI 协作」是稀缺的。这套系统补的就是这块。

## 二、分层（5 层，从下到上）

| 层 | 组件 | 一句话（是什么 / 解决什么） |
|---|---|---|
| **治理层** | wo.mjs（工单库）、autotake（自动接单）、routing-guard（派单守卫）、route-score（路由评分） | 把"活"拆成工单、派给对的窗口、卡了有人催、干得好权重涨 |
| **执行层** | 8 个 DSH 窗口 + ob.mjs（外脑状态机）+ run-task（自愈闭环） | 窗口接单干活；外脑把长任务状态落盘只喂切片；出错自动捕获回滚 |
| **记忆层** | digest（摘要）、reconcile（对账）、四层溯源、承诺簿、增量压缩 | 换会话不丢、AI 谎报能查、结论能追溯到原始、答应过的事不丢 |
| **情绪层** | endocrine（底色链）+ her-life + gaps | 小鱼有"底色"影响生活 chat 语气；工作层零情绪 |
| **成本层** | cost-daily（日报）、cost-ledger（台账）、真休眠、错峰 | 每天报花费、空转归零、高峰不跑 |

## 三、数据流（文字版）

```
任务入口
  ↓
信箱 mailbox → 窗口 take（自取）→ doing（干活，每10分钟报进度）
  ↓
submit（交证据）→ review → accept/reject（验收，eval 机器先判）
  ↓
done → 落完成笔记 + 记轨迹(trajectories.jsonl) → route-score 更新窗口权重
  ↓
下次派单 auto-assign 优先派给"这个类型干得最好的窗口"（reward 闭环）
```

工单池 `pool.json`（有锁+原子写）是所有窗口共享的"唯一真相"；channel.jsonl 是消息总线；wake-state.json 是休眠状态。

## 四、核心逻辑（"为什么这样设计"——这是最有价值的部分）

```
① 对账（reconcile）：AI 会谎报"做完了"，所以只信盘上事实，每天核对"它说做了 vs 实际做了没"
② 熔断（autotake）：任务失败→退回→重接→又失败，会死循环，所以同一任务来回 3 次自动冻结
③ scope 冲突（wo.mjs）：两张单改同一个文件会互相覆盖，所以领单前查"同 scope 有没有未结单"
④ 真休眠（wake-state）：窗口没活还每 20 分钟醒一次 = 纯烧钱，所以空闲就删巡检睡到 7:00/19:00，零 token
⑤ 懒加载常驻（tool-lazy）：工具插件 20 分钟不用就被卸载，工具就"消失"了，所以关键工具进常驻
⑥ SLA（autotake）：review 超 24h / doing 超 8h 就是"卡住了"，自动告警催
⑦ 缓存命中（前缀稳定）：prompt 前缀字节稳定就吃 0.02 元/M（全价的 1/50），所以静态段固定、动态段殿后
⑧ reward 闭环（route-score）：accept 奖励/reject 惩罚，路由越派越准，这是"自我进化"的落地版
⑨ 情绪隔离（endocrine）：情绪只影响生活 chat，工作层的验收/执行零情绪（心情差不能误杀合格交付）
```

## 五、设计原则（贯穿所有组件的三条）

```
① 不信任口头汇报，只信盘上事实（对账 + 证据 + 溯源）
② 空转归零，动态殿后（真休眠 + 前缀缓存 + 错峰）
③ 失败必须落盘、贴原文、可回滚（fail.mjs + 自愈 + CHANGELOG）
```

## 六、这套东西的价值（对外陈述用）

```
对"AI 应用"这件事，多数人停在"调 API 让 AI 答一句"；
这套系统解决的是"一群 AI 长期自主协作"的三件事：
  不翻车（对账/熔断/scope/SLA）
  不烧钱（真休眠/错峰/缓存命中/成本日报）
  不说谎（溯源/证据/eval 机器判/回填改进）

这三件事，是"模型无关的自主 agent 治理底座"的地基——
不绑定哪个模型，换个更强的模型（5090/多卡），这套底座直接搬过去继续用。
```
